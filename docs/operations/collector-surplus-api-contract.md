# Collector surplus API contract — version1

Frozen additive contract for491, using Treasury49008c31edd on isolated fixture565d9283. Implemented/readiness evidence belongs in the ledger; contract availability does not claim execution. No production setup. Backend owner implements models/service; clients use exact returned PHP strings and do not sum rows.

## Machine-readable commands

`collector-surplus-command-schema.json` beside this file is generated from the current strict Treasury command adapter (includes existing commands). It is the authoritative required/optional fields, literal action tags, decimal/UUID/date bounds and extra-forbidden shape. New own commands carry request_id+credit_id/credit_version or exception_id/exception_version and deliberately carry no account_id/expected_version. Server derives origin account/context and requires active registered actor/device and exact credited/original Collector. Staff commands use account_id/expected_version for that involved account; each other target version is explicit. Application commands are deliberately supported intent/blocked preparation, never false applied.

Base prefixes `/api/v1/treasury` and `/api/mobile/v1/treasury`. All JSON successes `{success:true,data:T}`. GET /requests/{request_id} returns exact durable TreasuryResult or data:null; null never authorizes retry/unlock. Auth is existing Authorization+X-Device-Id; workspace actor.device_id is registered core.devices UUID. No new offline outbox.

## Commands and phases

All use POST /actions and the machine schema. Only own requests/acknowledgments bypass account grants; they never approve debit/credit/reservation. Staff needs current active user/device + exact object + explicit per-account permission; recognition/settlement approver differs from credited Collector. Receiving additionally current remittance.receive and selected recipient. Owner-only opening prepare/activate. No broad permission grants seeded.

- collector_count_record records immutable count/evidence/current snapshot.0 valid. Short is saved rejected count, not accepted remittance. count_accept rechecks exact version/digest/physical acknowledgment and commits custody/full actual Treasury receipt+linked normal/extra+pending case+audit/outcome together. Old boolean receive/notification/mobile responses409 `{detail:{code:"collector_count_required",message:"..."}}` while feature enabled or surplus state retained; no inferred count. Plain rejection requires exact authority and no unresolved retained cash.
- collector_surplus_recognize needs source_review_acknowledged true, reviewed digest and independently retained recipient-purpose evidence/reason; partial capacity permitted; recognition has no new cash.
- collector_surplus_return_request records immutable own intent only. return_prepare references request id/version and identical amount/destination, independent staff and paying account; reserves capacity but no debit/outstanding reduction.
- Actual outgoing observation uses EXISTING disbursement_record with purpose `collector_surplus_return` or `collector_custody_exception_return`, source_id=approved action_record.id,source_version=action_record.version,payee_id=actual Collector, direction=debit, amount=exact approved principal,provider=paying account.kind,fee separately evidenced,reference/effective_at/evidence/attestation/reason under current disbursement.record+surplus.settle. No provider transfer. Generic result action remains disbursement_record; detail.source_link has action_record and disposition return_debited_confirmation_pending. Existing independently verified actual debit remains observable if business linking blocked; not a completed payout.
- Own return_acknowledge binds exact current action/event/credit or exception versions and reviewed principal, explicit received/not_received. Appends recipient fact, no money. Staff return_record binds exact acknowledgment/event/action and current paying account version; only verified received acknowledgment settles credit/exception capacity once. No amount/fee guessed from note or equal event amount. Wallet fee not charged to credit. Not_received stays reserved/pending.
- action_cancel requires correction evidence/reason and no known debit/uncertainty; rejects if linked event exists. No timeout automatically releases credit.
- application_request records opt-in own intent and exact same-Collector remittance/digest. application_prepare returns `blocked_adapter`; no reservation/credit consumption or physical1000 assertion for900 cash. Historical resolve_source returns `blocked_adapter`, or `recovery_required` if credit previously settled (freezes conflicting capacity, never negative credit). GL mapping stays explicitly unsupported; no automatic journal.
- opening_prepare/activate binds exact current active physical opening/collector/evidence/overlap review and independent owner. Immutable anchor uniqueness prevents repeat; adds no event/movement.
- custody_exception_record records separate real retained short cash with current count/evidence/holder and one physical event. Does not accept full remittance or grant credit. exception_return_prepare reserves remaining actual custody; existing disbursement records real outgoing; own exception_return_acknowledge and staff return_record prove return. Inclusion into later acceptance is explicitly blocked pending safe custody adapter. Legacy reject cannot pretend held cash returned.

## Durable result and errors

TreasuryResult retains `{contract_version:1,request_id,action,status:"saved"|"blocked",target_id,version,result}`. Surplus `result` always includes collector_surplus_contract_version1,disposition,actor_user_id,device_id,account_id,ledger_context_id,source_account_id|null,blockers[], and slots count,settlement,case,credit,request,action_record,acknowledgment,exception,opening_anchor (each row or null). target_id/version bind the phase's principal returned row. New outgoing observation remains existing event-shaped result; source_link adds action_record/disposition.

Dispositions: counted_ready,counted_short_rejected,accepted_exact,accepted_pending_identification,recognized,requested,reserved,return_debited_confirmation_pending,acknowledged_received,acknowledged_not_received,paid,exception_returned,cancelled,opening_prepared,opening_activated,custody_exception_recorded,blocked_adapter,recovery_required. `saved` may mean short rejected, requested or reserved. Never show Received/Paid until exact disposition+identities+source/amount validate. Root blocked outcome is authoritative blocked, not transport uncertainty.

403 current authority/recipient/own scope/file denied;409 versions/digest/capacity/identity/changed replay conflicts;422 strict schema;503 disabled/unconfigured setup. Header/body unexpected actor/target/result stays uncertain; GETnull stays locked. Same key replay requires current user/device/account/source/file authority and identical body hash. Source/event uniqueness also holds across other keys/devices. No financial automatic resend/retry after resume.

Entry flag SPINA_COLLECTOR_SURPLUS_ENABLED defaultsfalse and requires Treasury readiness. Existing records/read/outcome recovery remain visible after disable. ## Additive reviewed API refinements

Surplus account actions use short capability names (count_record,count_accept,etc), including evidence_upload. recipient-purpose upload permits live/scoped receive/resolve/settle as well as existing receipt.verify; opening-purpose remains owner-only. Own intent destination keeps recipient_reference. Current action detail adds acknowledgment:{full acknowledgment DTO|null}. Workspace adds opening_choices:[{id,account_id,version,cutoff,amount,status:'active'}], owner-only active physical openings. Remittance safe rows expose both id/remittance_id exactsameUUID, source_digest|null,gross_obligation,refund_due_total,physical_cash_required,application_request_supported; no own borrower snapshot. Optional mode=own|staff lets a Collector with independent staff grants select own view; default prefers authorized staff scope.

GET export returns the same success/data Workspace envelope, all authorized selected-kind items, has_more:false, with private attachment/no-store.

collector_surplus_return_reverse is a staff command with account_id/expected_version,action_id/action_version,amount,provider,reference,effective_at,evidence_id,recipient_attestation,reason. Requires settle and disbursement.record on paying account and settle on origin. It records a real independently observed incoming principal reversal using existing record_verified_event, links the event once, appends return_reversal credit entry and reopens only amount<=previously paid principal not already reversed. Pending/unconfirmed debit cannot reopen credit. Original debit remains immutable; fees are not silently reversed. Result disposition return_reversed adds incoming_event and action_record.reversed_amount; action status partly_reversed|reversed. No income or second movement.
